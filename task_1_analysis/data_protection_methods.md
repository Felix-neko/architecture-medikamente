# Список данных для защиты и способы защиты

Документ содержит классификацию данных компании «Медикаменте» с указанием рекомендуемых способов защиты: **шифрование**, **обфускация** (маскировка), **обезличивание** (анонимизация/псевдонимизация).

---

## Классификация данных по уровням конфиденциальности

| Уровень | Описание | Примеры |
|---------|----------|---------|
| **Критический** | Особые категории ПДн, врачебная тайна | Диагнозы, результаты анализов, ВИЧ-статус |
| **Высокий** | Персональные данные | ФИО, паспортные данные, дата рождения |
| **Средний** | Контактные и операционные данные | Телефон, email, адрес |
| **Низкий** | Обезличенные и публичные данные | Статистика, агрегированные отчёты |

## Рекомендуемые алгоритмы и подходы

### Шифрование

| Сценарий | Алгоритм | Примечание |
|----------|----------|------------|
| **At Rest (БД)** | AES-256-GCM | Шифрование на уровне полей или колонок |
| **At Rest (файлы)** | AES-256 | Шифрование медицинских изображений, сканов |
| **In Transit** | TLS 1.3 | Все соединения внутри сети и с внешними системами |
| **Ключи шифрования** | RSA-4096 или ECDSA | Для обмена симметричными ключами |
| **Хэширование паролей** | Argon2id или bcrypt | Для учётных записей |

### Обфускация (маскировка)

| Тип данных | Метод маскировки | Пример |
|------------|------------------|--------|
| **ФИО** | Частичное скрытие | Иванов И.И. → И****в И.И. |
| **Телефон** | Маска середины | +7 (999) 123-45-67 → +7 (***) ***-45-67 |
| **Email** | Маска домена и имени | ivan.petrov@mail.ru → i***@***.ru |
| **Паспорт** | Последние цифры | 1234 567890 → **** ****90 |
| **Карта** | PAN masking | 4276 1234 5678 9012 → **** **** **** 9012 |

### Обезличивание (анонимизация/псевдонимизация)

| Метод | Описание | Применение |
|-------|----------|------------|
| **Псевдонимизация** | Замена идентификаторов на псевдонимы с возможностью обратного преобразования | Внутренняя аналитика, исследования |
| **K-анонимность** | Группировка записей так, чтобы каждая комбинация атрибутов встречалась минимум K раз | Публикуемые статистические данные |
| **L-разнообразие** | Обеспечение разнообразия чувствительных атрибутов в группе | Защита от атак на k-анонимность |
| **Дифференциальная приватность** | Добавление шума к агрегированным данным | ML-модели, публичные отчёты |
| **Генерализация** | Обобщение значений (возраст → диапазон, город → регион) | BI-отчёты |
| **Удаление** | Полное удаление идентифицирующих атрибутов | Открытые датасеты |

## Рекомендации по внедрению

1. **Шифрование at Rest:**
   - Внедрить TDE (Transparent Data Encryption) для БД
   - Использовать шифрованные файловые системы для медицинских изображений
   - Централизованное управление ключами (HSM или Vault)

2. **Шифрование in Transit:**
   - TLS 1.3 для всех внутренних и внешних соединений
   - mTLS для межсервисного взаимодействия
   - VPN для удалённого доступа

3. **Обфускация:**
   - Реализовать на уровне API/UI
   - Разные уровни маскировки для разных ролей
   - Логировать запросы на полные данные

4. **Обезличивание:**
   - Создать отдельный слой данных для аналитики
   - Автоматизировать процесс псевдонимизации при выгрузке
   - Регулярно проверять на возможность реидентификации
