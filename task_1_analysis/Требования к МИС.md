# Требования к МИС

## Основные требования

Поддержка работы на небольшую сеть поликлиник (не более 10 филиалов, не более 300 сотрудников).

Интеграция с 1С:Бухгалтерией (и с ККМ через неё).

Централизованное хранение медицинских карт, журналов записи, журналов приёма, списков пациентов и другой медицинской документации, исключающее коллизии при попытке изменения данных с нескольких рабочих мест одновременно.

Поддержка RBAC для разных типов сотрудников, ограничение доступа к медицинским картам пациентов (в идеале – полный доступ имеет только лечащий врач и сам пациент).

Интеграция с клиническими лабораториями для автоматизации заявок на анализы и печати штрих-кодов.

Интеграция со страховыми компаниями для автоматизации заявок на согласование процедур и получения подтверждений / отказов.

Возможность прикладывать к медицинской карте объёмные файлы (например, файлы со снимками МРТ, рентгеновскими снимками, ЭКГ и др.), желательно с их хранением в отдельном S3-хранилище.

## Требования для веб\-портала пациентов

* возможность обращаться к МИС по REST API и получить:  
  * список специалистов в каждом филиале;  
  * их часы работы в заданный день;  
  * какие часы у них ещё не заняты записями;  
* возможность обратиться по REST API и создать запись к заданному специалисту на заданную дату;  
* возможность онлайн-оплаты медицинских услуг (т.е. интеграция с платёжными шлюзами и интернет-эквайрингом);  
* возможность обращаться по REST API для просмотра своей медицинской карты;  
* желательна поддержка веб\-хуков: чтобы МИС могла отправлять сообщение нашему порталу для пациентов каждый раз, когда происходит создание, отмена или перенос записи (чтобы портал инвалидировал кэш страницы с расписанием врачей);  
* желательна поддержка напоминаний о записях через мессенджеры

# Требования для экспорта в аналитическую БД

Так как мы хотим прикрутить к МИС ещё и аналитическую БД для офлайн-аналитики, нужна дополнительная функциональность.

* Нужен доступ по REST API ко всем медицинским документам, хранящимся в БД (из-под отдельной технической учётки).  
* Желательна поддержка веб\-хуков на обновление данных в МИС: чтобы в этот момент происходил экспорт обновлений “на лету” в аналитическую БД.

## Прочие требования

* возможность использования зашифрованной базы данных  
* \[желательно\] интеграция с системами электронной очереди.  
* \[желательно\] возможность отдельного хранения идентифицирующих полей пациентов  
* \[желательно\] логирование действий пользователей по получению доступа к данным
