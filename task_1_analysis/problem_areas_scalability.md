# Проблемные зоны архитектуры с точки зрения бизнес-операций

Анализ проблемных зон текущей архитектуры компании «Медикаменте» с точки зрения влияния на бизнес-процессы при масштабировании до сети из 5-6 клиник.

---

## Список проблемных зон

| № | Проблемная зона | Текущая реализация | Проблема при масштабировании |
|---|-----------------|--------------------|-----------------------------|
| 1 | **Хранение данных в Excel** | Список пациентов, журналы записей — всё в Excel-файлах на сетевой ФС | Коллизии при одновременном доступе, потеря данных, невозможность параллельной работы. Уже сейчас бывают коллизии при 2 администраторах — при 15+ администраторах из разных филиалов ситуация станет критической |
| 2 | **Единственный физический сервер** | Один сервер Windows Server 2022 в здании офиса (AD, DNS, файловый сервер, Exchange, 1С) | Single Point of Failure: отказ сервера останавливает все филиалы. Сервер не в ЦОД, а в клинике — нет гарантий по каналам связи и SLA |
| 3 | **Локальная сетевая папка для медкарт** | Медкарты хранятся в папках на файловом сервере | При работе через VPN — задержки и коллизии. Вариант «по серверу на филиал» требует ручной синхронизации медкарт, что утомительно и гарантирует потери данных |
| 4 | **1С в файловом режиме** | 1С:Бухгалтерия и 1С:Торговля работают с файловыми базами | Файловый режим поддерживает максимум 5-10 пользователей. При большем количестве — блокировки и падение производительности |
| 5 | **Отсутствие API и интеграций** | Ручной ввод данных, копирование между системами | Ручной ввод × 5 филиалов = не 5×, а на порядок больше ошибок из-за коллизий и рассинхронизации. Невозможно построить сквозные бизнес-процессы |
| 6 | **Нет клиентского портала и мобильного приложения** | Запись только через телефон или личную явку | Нет возможности для самостоятельной записи пациентов через интернет. Конкуренты с онлайн-сервисами будут привлекательнее |

---

## Детальный анализ проблемных зон

### 1. Хранение данных в Excel-файлах

**Текущее состояние:**
- Список пациентов — единый файл `patients.xlsx` на сетевой ФС
- Журналы записей — отдельные файлы вида `/Записи/{дата}/{специалист}.xlsx`
- Медкарты — папки с файлами на сетевом диске

**Проблемы при масштабировании:**

При развёртывании сети клиник неизбежен выбор между двумя плохими вариантами:

**Вариант А: один сервер на все филиалы (через VPN)**
- При 5 филиалах будет ~15 администраторов, одновременно работающих с файлами
- Excel не поддерживает параллельное редактирование с гарантией целостности
- Уже сейчас бывают коллизии при 2 администраторах — при 15+ администраторах это станет критичным
- Сбои во всех филиалах при временной потере связи с центральным сервером

**Вариант Б: по серверу на каждый филиал**
- Списки пациентов и медкарты надо синхронизировать вручную в конце рабочего дня
- Гарантированы потери данных из-за ошибок при ручной синхронизации
- Проблемы с доступом к журналам записей других филиалов

---

### 2. Единственный физический сервер

**Текущее состояние:**
- Один сервер Windows Server 2022 в здании офиса
- На нём размещены: AD, DNS, DHCP, файловый сервер, Exchange, 1С

**Проблемы при масштабировании:**
- Single Point of Failure — отказ сервера останавливает всю компанию и все филиалы
- Сервер стоит не в дата-центре с резервированными каналами и хорошим SLA, а прямо в клинике
- Нет географической распределённости для филиалов
- Производительность не масштабируется вертикально бесконечно

---

### 3. Локальная сетевая папка для медкарт

**Текущее состояние:**
- Медкарты хранятся в папках на файловом сервере Windows
- Путь: `\\server\medcards\{patient_id}\`

**Проблемы при масштабировании:**
- Филиалы не имеют прямого доступа к сетевой папке — нужен VPN
- Работа через VPN будет медленной (особенно для больших файлов диагностики: рентген, УЗИ)
- Нет версионирования документов — риск потери данных при коллизиях
- Если делать «по серверу на филиал» — ручная синхронизация медкарт крайне утомительна и гарантирует потери

---

### 4. 1С в файловом режиме

**Текущее состояние:**
- 1С:Бухгалтерия и 1С:Торговля в файловом режиме
- Данные в файлах `.1cd` на сетевом диске

**Проблемы при масштабировании:**
- Файловый режим поддерживает максимум 5-10 одновременных пользователей
- При большем количестве — блокировки и падение производительности
- Нет возможности работы из удалённых филиалов без VPN
- Резервное копирование — копирование файлов (не консистентное при активной работе)

---

### 5. Отсутствие API и интеграций

**Текущее состояние:**
- Данные вводятся вручную в каждую систему
- Нет автоматического обмена между Excel, 1С, порталами партнёров

**Проблемы при масштабировании:**
- Ручной ввод × 5 филиалов = не 5×, а на порядок больше ошибок из-за коллизий и рассинхронизации данных между филиалами
- Невозможно построить сквозные бизнес-процессы между филиалами
- Интеграция с внешними системами (ЕГИСЗ, лаборатории) требует API, которого нет

---

### 6. Нет клиентского портала и мобильного приложения

**Текущее состояние:**
- Взаимодействие с пациентами только офлайн или по телефону
- Результаты анализов приходят по email

**Проблемы при масштабировании:**
- Нет возможности для самостоятельной записи пациентов через интернет
- Конкуренты с онлайн-сервисами будут привлекательнее для клиентов
- Отсутствие удобных способов записи отпугивает потенциальных клиентов

---

## Резюме

Текущий IT-ландшафт компании **не позволяет нормально работать при развёртывании сети клиник**. Основные блокирующие проблемы:

1. **Коллизии при работе с Excel-файлами** — уже сейчас создают проблемы, при масштабировании станут критичными
2. **Single Point of Failure** — единственный сервер без резервирования
3. **Невозможность автоматизации** — ручной ввод и синхронизация не масштабируются
